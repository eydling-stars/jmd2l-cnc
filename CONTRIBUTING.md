# Как доработать проект

Спасибо, что смотрите. Проект открытый: форкните, правьте, присылайте изменения.
Ниже — короткий порядок, чтобы правка не превратилась в отладку вслепую.

## Что стоит прочитать до первой правки

| Файл | Зачем |
|---|---|
| [CONTEXT.md](CONTEXT.md) | термины и границы предметной области — чтобы называть вещи одинаково |
| [docs/SPEC.md](docs/SPEC.md) | что система должна и чего не должна делать; здесь же протокол обмена целиком |
| [docs/adr/](docs/adr) | почему ключевые решения приняты именно так; менять их — значит писать новую ADR |
| [docs/MANUAL.md](docs/MANUAL.md) | как всё выглядит у пользователя |

## Три команды, которые нужны чаще всего

```powershell
# запустить панель из папки репозитория (нужны node и npm install в server\)
start.cmd

# собрать и прошить плату из исходников
powershell -ExecutionPolicy Bypass -File bench\flash.ps1 -Port COM4

# прогнать 37 автопроверок протокола — моторы не нужны
powershell -ExecutionPolicy Bypass -File bench\jmd2l_test.ps1 -Port COM4 -ShortRunSec 20
```

Правило: **правки прошивки, задевающие безопасность, не принимаются без зелёных
автотестов**. Это относится и к обрыву связи, и к логике концевиков, и к
аварийным кодам.

## Куда что класть

| Правка | Файл |
|---|---|
| поведение платы, протокол, защита | `firmware/jmd2l_cnc/jmd2l_cnc.ino` |
| обмен с платой, порты, поток событий | `server/server.js` |
| вкладки, журнал, графики, стенд | `web/app.js`, `web/settings.js`, `web/setup.js`, `web/bench.js`, `web/index.html` |
| установка, тихая установка, удаление | `install/install.ps1` |
| тексты для пользователя | `docs/MANUAL.md`, затем `docs\build-doc.ps1` пересобирает `.docx` |

`.docx` в репозитории — производный файл. Правьте `MANUAL.md`, потом:

```powershell
powershell -ExecutionPolicy Bypass -File docs\build-doc.ps1
```

## Соглашения

- Коммиты и сообщения — **по-русски, коротко, по смыслу**:
  «Правка `resolveLimitSide`: отвод только в сторону от концевика».
- Стиль — как в соседних файлах: 2 пробела, без табов, Windows-1251 не нужен,
  файлы в UTF-8.
- Скрипты PowerShell — **с BOM и переводами строк LF**. Без BOM PowerShell 5.1
  читает кириллицу как мусор, это уже стоило времени.
- Прошивка не хардкодит номера версий инструментов и номера выводов модулей,
  которые человек определяет тестером.
- Настройки платы лежат в одном массиве `cfg` из 43 значений. Не добавляйте
  элементы в середину — это ломает сохранённые настройки у всех, кто уже
  прошивался. Новые настройки — в конец, со значением по умолчанию.

## Pull request

1. Форк, своя ветка от `main`.
2. Правка + прогон автотестов, в описании — что именно изменилось и почему.
3. Если изменилось поведение пользователя — правка `docs/MANUAL.md` и запись в
   `CHANGELOG.md` в том же PR.
4. Обратная совместимость настроек не должна ломаться. Если ломается — это
   отдельное решение, а не побочный эффект правки.

## О безопасности

Станок режет металл. Прежде чем менять логику движения, защиты или отказа:

- прочитайте [§13 руководства](docs/MANUAL.md) и
  [ADR 0003](docs/adr/0003-protection-stops-axes-relay-is-output.md);
- помните: реле шпинделя — это **выход** платы, а не вход. Защита обязана
  останавливать оси и обесточивать шпиндель сама, без участия компьютера;
- ограничитель скорости и кнопка аварийного останова — часть схемы, а не
  опция. Не предлагайте их убрать как «необязательные» ([§5.2](docs/MANUAL.md)).

## Чего делать не стоит

- Прошивать плату, подключённую к собранному станку, без разрешения на ход.
- Проверять движение по стенду с подменой датчиков на собранном станке —
  ограничения в [§15.2](docs/MANUAL.md).
- Считать `avrdude` успешной прошивкой по коду возврата. Признак успеха —
  строка `N bytes of flash verified`.
- Тащить в репозиторий скомпилированные бинарники Arduino-тулчейна. Для
  прошивки готовая `.hex` лежит в `firmware/prebuilt/`, а инструменты собираются
  скриптом `install\fetch-arduino.ps1`.
